## 收益

1. 原策略不用新增年级分支；报名主类不需要知道哪类活动限定年级。
2. 邮件追加观察者，站内通知保留；报名不认识邮件发送器。
3. 新策略可独立测试；事件故障可注入，失败不影响已经提交的报名。
4. 配置与迁移有独立验证，旧库不必清空重建。

## 代价与不足

新规则涉及字段、数据库 CHECK、工厂注册、页面选项和演示数据，不是加一个类就结束。为防并发，数据库也维护容量和状态保护，规则存在有意重叠，维护时必须同步测试。

Observer 异常隔离不等于可靠投递；未引入事务发件箱或补偿任务。模拟邮件失败不会自动重试，界面显示失败供验收。真实 SMTP 若引入外部副作用，现有唯一记录策略不足以保证外部“恰好发送一次”。

初版策略接口仍包含直接策略不支持的 `review()`，没有为追求指标重新拆接口。当前通过禁止待审核时切换报名方式降低异常路径，但这不等于完整满足 LSP。

本次没有另写一套无模式系统来制造对照，比较的是同一项目的真实版本。签名、人工判断、上线状态和截图来源均须如实说明。

## 复现差异与指标

```bash
git diff baseline-v1 change-v2 -- src tests templates
git log --oneline baseline-v1..change-v2
python tools/verify_release.py
```

脚本重新读取初版源码并以 AST 比较类，不用预填常数计算指标。测试运行会更新机器时间和日志，应在独立克隆或明确允许更新证据时执行。
