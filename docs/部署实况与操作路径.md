## 二、关键结论（踩坑记录）

### 结论 1：免费额度限制的是「项目数」，不是「服务数」

Railway Free 计划（官方 pricing 确认）：

| 限制项 | 免费额度 |
|---|---|
| **Projects（项目数）** | **1 个** ← 超出则提示需付费升级 |
| **Services per project（每项目服务数）** | **3 个** ← 一个项目内可放 3 个服务 |

因此：**正确做法是在已有项目里新增 Service，而不是新建项目。**

### 结论 2：`railway up` 不能用来往已有项目加服务

实测过程：

```bash
railway link -p 5724c88b-...        # 关联到已有项目 ✅
railway up --detach -y              # 部署
```

结果：`railway up` 创建了一个**游离服务**（id `fa18d90c-588e-4ce4-b59f-879d618c6929`），
**它没有落进任何项目**。后续查询该服务时返回：

```
Service 'fa18d90c-588e-4ce4-b59f-879d618c6929' not found
```

即：**CLI 无法把服务塞进指定的已有项目**，该服务游离且没有域名（探测各种命名组合均 404）。

> 结论：**必须走网页端操作**（New → Service），CLI 这条路走不通。

### 结论 3：`railway link -s <serviceId>` 无效

`railway link -s` 的参数被 CLI 忽略，始终自动选中列表中的第一个服务（`studytask`）。
要操作指定服务，只能通过网页端。

### 结论 4：CLI 的服务列表只显示「当前 link 的项目」下的服务

即使账号下有多个项目，`railway status` 也只显示当前关联项目的那一个服务。
排查时需逐个 `railway link -p <projectId>` 切换查看。

## 三、操作路径（网页端，3 步）

### 步骤 1 · 进入项目并新建 Service

1. 打开 <https://railway.com/dashboard>
2. 进入 **`beautiful-abundance`** 项目（它只有 1 个服务，还有 2 个空位）
3. 点 **＋ New** → **Service** → **GitHub Repo** → 选择 **`cql123-love/CampusEvent`**

> 若仓库列表里没有：点 **Configure GitHub App** →
> Repository access 选 *Only select repositories* → 勾选 `CampusEvent` → **Install** → 回到 Railway 点 **Refresh**

### 步骤 2 · 确认构建配置

新建的 Service 会自动读取仓库根目录的 `railway.json`，无需手填。若需核对：

| 配置项 | 值 |
|---|---|
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app --bind 0.0.0.0:$PORT` |
| Healthcheck Path | `/` |
| Root Directory | 留空（**不要设为 src**，templates/static 在仓库根）|
| 环境变量 | `CAMPUSEVENT_DB=/tmp/campusevent.db`（可选）|

### 步骤 3 · 生成公网域名

**Settings → Networking → Generate Domain** → 得到 `https://<服务名>-production-<hash>.up.railway.app`

然后回填到：
- `README.md` 的「一、在线地址」
- `docs/作业提交说明.md` 的答案栏
