# CampusEvent 部署方案（在已有 Railway 项目内新增 Service，免绑卡）

## 背景：为什么不能用"新建项目"

Railway 免费计划的限制是：

| 限制项 | 免费额度 |
|---|---|
| **Projects（项目数）** | **1 个** ← 新建第 2 个项目需付费升级 |
| **Services per project（每项目服务数）** | **3 个** ← 一个项目内可放 3 个服务 |
| Service domains（每服务域名） | 2 个 |
| 绑卡要求 | **无需信用卡** |

因此正确做法是：**不新建项目，而是在已有的 StudyTask 项目里新增一个 Service**，
该 Service 指向 CampusEvent 仓库。

---

## 方式一：网页端（推荐，3 步）

1. 打开 <https://railway.com/dashboard> → 进入你已有的那个项目（部署 StudyTask 的那个）
2. 项目页面里点 **＋ New** → **Service** → **GitHub Repo** → 选择 **`cql123-love/CampusEvent`**
   - 若列表里没有 → 点 **Configure GitHub App** 授权（选 *Only select repositories*，勾选 `CampusEvent`）→ Refresh
3. 新 Service 建好后：
   - **Settings → Deploy**：`gunicorn app:app --bind 0.0.0.0:$PORT`（应已自动读取 `railway.json`）
   - **Settings → Networking → Generate Domain** → 得到 `https://xxx.up.railway.app`

> 同一个项目里的两个服务（StudyTask / CampusEvent）各自独立，域名互不影响。

## 备选：PythonAnywhere（真正零成本、且从不休眠）

- 免信用卡，1 个免费 Web 应用，域名 `xxx.pythonanywhere.com`
- **不会休眠**（Render 15 分钟休眠，Railway 免费版也会 sleep）
- 缺点：需手动配置 WSGI（约 10 分钟操作）

---

## 三平台对比

| 平台 | 绑卡 | 多项目/多服务 | 休眠 | 备注 |
|---|---|---|---|---|
| **Railway（现有项目加服务）** | 免卡 | 1 项目 / 3 服务 | 会 sleep | **无需新建项目，推荐** |
| Render | 免卡（若强制绑卡则不行） | 多服务 | 15 分钟休眠 | 部署最省事 |
| PythonAnywhere | 免卡 | 1 个 web app | **不休眠** | 需手动配 WSGI |
