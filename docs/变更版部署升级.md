# 变更版部署升级

当前公网地址为 `http://101.35.250.91/`。**仓库新功能已本地验证，不表示腾讯云已更新。** AI 没有服务器登录凭据，本次没有执行生产升级，也不要求用户发送密码或密钥。

旧部署使用 `~/CampusEvent/instance/campusevent.db`。不要删除目录、删库、`seed.py --force` 或重新部署来清空历史。云资源是否收费、何时到期以账号控制台为准，本次未购买服务或开启续费。

## 在腾讯云终端执行

以 `ubuntu` 用户进入原目录，先检查是否有自己修改过的文件：

```bash
cd ~/CampusEvent
git status --short
git fetch origin --tags
git switch --detach change-v2
bash deploy/upgrade.sh
```

如果 `git switch` 提示本地修改会被覆盖，停止并保留这些修改，不使用强制切换。脚本要求工作区干净、当前提交等于 `change-v2`、原服务正在运行。

脚本会先安装依赖并测试，再停止 `campusevent`、使用 SQLite backup API 生成带时间的备份、事务升级、检查外键和版本，最后重启。备份位于 `instance/backups/`，不会提交 Git。迁移出错时事务回滚，脚本停止并保留备份，不自动删除数据。

## 升级后验收

1. 浏览器查看页面 HTML，存在 `data-release="change-v2"`，确认访问的不是旧服务。
2. 管理后台新建“年级限定直接报名”活动，时间设为未来、容量 2。
3. 首页切换 S001（年级 1）报名：应提示仅限大二、大三；S002、S003 应通过；S004 应拒绝。
4. 切到 S002 的“我的消息”：同时有站内结果和模拟邮件，字段含收件人、主题、正文、状态、时间。
5. 建审核活动，分别批准、拒绝，检查双渠道；重复审批不得重复通知。
6. 执行 `sudo systemctl restart campusevent`，刷新确认上述活动、报名和邮件仍保留。

测试邮件失败可在独立本地演示环境设置 `CAMPUSEVENT_MOCK_EMAIL_FAIL=1`，不应为了验收随意改变生产所有人的通知结果。自动故障测试已覆盖直接和审批结果。

升级成功后不要把本机截图冒充公网记录。请保留实际终端输出和浏览器结果，再更新 `docs/公网部署验收.md` 中的变更版状态。

## 失败处理

```bash
sudo systemctl status campusevent --no-pager
sudo journalctl -u campusevent -n 80 --no-pager
ls -lh instance/backups/
```

不要向 AI 粘贴 `production.env` 内容。迁移后不能直接切回旧版并继续使用新库，因为旧版本不支持新策略；需要停服务，由用户明确选择恢复对应升级前备份和旧代码。保留新旧库，不自动覆盖它们。
