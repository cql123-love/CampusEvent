# 变更版设计原则与决策

本文件描述实际实现；`00_设计决策说明.md`、`05_设计原则说明.md` 保留为初版历史材料，其中与当前源码不一致的内容以本文件、变更图和测试为准。初版签名栏仍为空，不能据历史文档措辞声称已经取得同学签名。

## 1. 策略：扩展资格，不扩散类型判断

`GradeLimitedDirectPolicy` 继承 `DirectPolicy`，只在 `submit()` 拒绝非 2、3 年级；合格后调用父类。普通直接报名与审核型策略没有加入年级判断。策略不访问数据库、不发通知、不复制名额与时间规则。

`RegistrationService` 继续通过 `PolicyFactory.create()` 获取抽象策略；其类 AST 与 `baseline-v1` 一致。`BusinessError` 移到 `errors.py` 消除循环依赖，但仍从 `services.py` 导入，因此旧测试和路由兼容。

代价：除了新策略，还必须改工厂注册表、类型常量、学生仓储、SQLite 约束、后台校验和界面。不能据“核心报名类未改”推导“全项目零修改”。没有为了新增一项资格引入通用规则引擎。

## 2. 公共规则与数据库最终约束

服务层负责按业务顺序校验：活动/学生存在、活动未开始、无有效重复、策略判断、按初始状态检查名额、保存、发布事件。审核型待审核不占名额；批准时再次查名额。

两个请求可以同时通过前置查询，因此新增数据库保护：

- 有效报名部分唯一索引，约束同一学生、同一活动最多一条待审核或已通过记录。
- 容量触发器，在插入已通过记录或转为已通过时检查容量。
- 容量调整触发器与待审核报名的方式修改触发器，保护活动编辑。
- 报名更新带合法原状态条件，拒绝陈旧审批和重复取消；不允许后到请求覆盖已经处理的状态。

这些属于最终数据一致性约束，不替代服务层的规则说明。代价是部分规则同时体现在服务和数据库中；新增状态时须同步维护并测试。没有宣称采用“纯策略化”消除所有校验。

## 3. 观察者：追加渠道，保持事务隔离

`AppContainer` 同时订阅 `MessageNotifier`、`EmailNotifier`。站内消息仍覆盖原事件；邮件只处理已通过、已拒绝。`RegistrationService` 不认识发送器、不检查渠道类型。

报名写入的 `COMMIT` 在 `publish()` 前。每个订阅者独立处理异常；邮件故障不回滚报名，不阻止站内消息。原发布者曾直接吞掉异常，现增加应用错误日志；站内通知也不再把所有 `IntegrityError` 都误当成重复。

`MockEmailSender` 不做网络发送，演示地址为 `student_id@campusevent.invalid`。数据库记录本身就是模拟发送的可观察结果。`MockEmailRepository.record_once()` 按 `(registration_id,event_type)` 唯一键写入；失败邮件及其错误日志同事务保存。多线程和重启后的重复事件不会新增记录。

局限：模拟失败不自动重试；进程若在报名提交后、事件发布前崩溃，可能缺通知。没有消息队列、事务发件箱或最终送达保证。不能把 Mock 的唯一记录保证宣传成真实 SMTP 的“恰好一次投递”。

## 4. SOLID 的收益与限制

| 原则 | 实际体现 | 保留的限制 |
|---|---|---|
| SRP | 实体描述数据；策略决定规则结果；仓储持久化；订阅者处理渠道 | 服务仍有多个相关报名操作；数据库保护有意与前置规则重叠 |
| OCP | 新增年级策略、新增邮件订阅者；核心报名类未改 | 注册、数据结构、组装、界面仍需改，不能声称完全关闭修改 |
| LSP | 新直接策略沿用直接策略语义，仅对自身新活动类型加资格 | 原抽象含 `review()`，直接策略仍不支持审批，不能当作所有策略都可审批 |
| ISP | `Observer` 只需要 `update(event)` | 策略接口仍包含直接报名不需要的审批方法，是已知取舍 |
| DIP | 服务经策略工厂和抽象调用；发布者只识别观察者协议 | 仓储未另建抽象接口，靠构造注入与鸭子类型；不夸称所有依赖均为接口 |

没有同时维护另一套无模式实现。维护性分析比较真实初版与变更版，不假造对照工程。

## 5. 旧缺陷与迁移

活动开始改为比较精确时间；无效日期在创建、编辑时拒绝，已有坏日期按已关闭处理。所有时间按 Asia/Shanghai 的无时区墙上时间，拒绝带偏移的输入，避免混合比较。

有任意报名历史的活动拒绝删除；有待审核报名时拒绝切换方式。另修复页面把方法对象当布尔值而阻止再次报名的问题，以及导航切换学生后丢身份的问题。

SQLite 旧表增量迁移并保留 ID、历史和通知；不补发旧邮件。未知账号默认一年级，不从学号猜测。事务验证失败时回滚。线上升级工具先用 SQLite backup API 备份，脚本停止服务写入后迁移。
