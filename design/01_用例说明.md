## 一、参与者（Actor）

| 参与者 | 说明 | 权限边界 |
|---|---|---|
| **Student（学生）** | 浏览活动、查看详情、报名、取消报名、查看站内消息 | 只能操作**自己的**报名与消息；不能创建/删除活动，不能审批 |
| **Admin（管理员）** | 创建/编辑/删除活动、审批报名、查看统计 | 使用**固定演示账号**登录（指导书允许，无需完整权限系统） |

> 指导书原文："角色包括 Student（学生）与 Admin（管理员），可使用固定演示账号。无需用户注册和复杂权限系统。"

## 二、用例清单（对应指导书 P2-F01 ~ P2-F08）

### UC-01 管理活动（P2-F01）

| 项 | 内容 |
|---|---|
| **主参与者** | Admin |
| **前置条件** | Admin 已登录 |
| **触发** | Admin 在活动管理页提交表单 |
| **后置条件** | 活动记录持久化到 `activities` 表；成功后可在列表中看到 |
| **主流程** | 1. Admin 填写：标题、类型(category)、开始时间(start_at)、地点(location)、人数上限(capacity)、报名方式(policy_type)<br>2. 提交<br>3. 系统校验：标题非空、capacity 为正整数、开始时间合法<br>4. 系统保存活动<br>5. 跳转列表并提示"活动创建成功" |
| **备选流程** | 3a. 标题为空 → 提示"活动名称不能为空"，不保存<br>3b. capacity ≤ 0 或非整数 → 提示"人数上限必须为正整数"，不保存<br>3c. policy_type 非法 → 提示"报名方式无效" |
| **业务规则** | B.1（容量为正整数） |

**扩展：编辑活动** — Admin 修改上述字段，同样走校验；不允许修改到已报名活动导致的名额小于已通过数（超出范围则提示）。
**扩展：删除活动** — Admin 删除活动。**若该活动存在"待审核"或"已通过"的报名，拒绝删除并提示**（见设计决策第 3 项）；若无任何有效报名，允许删除（级联删除其报名与消息记录）。

### UC-02 浏览与筛选活动（P2-F02）

| 项 | 内容 |
|---|---|
| **主参与者** | Student、Admin |
| **前置条件** | 无 |
| **后置条件** | 无 |
| **主流程** | 1. Student 打开活动列表页<br>2. 系统按开始时间升序展示活动：标题、类型、时间、地点、剩余名额、报名方式标签<br>3. Student 输入名称关键字 → 系统按标题模糊筛选，结果只含匹配活动 |
| **备选流程** | 3a. 关键字为空 → 展示全部活动 |
| **扩展** | 点击活动 → 进入活动详情页（UC-02b），显示活动信息 + 已通过数 + 待审核数 + 剩余名额 + 我的报名状态 |

---

### UC-03 学生报名（P2-F03 / P2-F04）

| 项 | 内容 |
|---|---|
| **主参与者** | Student |
| **前置条件** | Student 已登录；活动存在且未开始 |
| **后置条件** | 生成一条 Registration 记录；生成一条站内消息 |
| **主流程** | 1. Student 在活动详情页点击"报名"<br>2. 系统按顺序执行：<br>　2.1 活动存在校验<br>　2.2 活动未开始校验<br>　2.3 无重复有效报名校验<br>　2.4 名额校验<br>　3. **策略介入**：直接报名 → 状态"已通过"；审核型 → 状态"待审核"<br>4. 保存报名记录（事务提交）<br>5. 发布事件 → 观察者写入站内消息<br>6. 提示"报名成功"或"报名已提交，等待审核" |
| **备选流程** | 2.1a. 活动不存在 → 提示"活动不存在"<br>2.2a. 活动已开始 → 提示"活动已开始，报名通道已关闭"<br>2.3a. 已存在"待审核"或"已通过"的报名 → 提示"不可重复报名"<br>2.4a. 名额已满 → 提示"名额已满"<br>5a. 通知写入失败 → **报名记录仍保留**，失败信息记入通知日志 |
| **业务规则** | B.2 规则 1/2/3/4/5/6 |

**关键说明：** 第 3 步是唯一使用策略的地方。报名方式决定"提交后是什么状态"，其余全是公共规则。

---

### UC-04 取消报名（P2-F03 / P2-F06）

| 项 | 内容 |
|---|---|
| **主参与者** | Student |
| **前置条件** | 存在一条属于该学生的报名，状态为"待审核"或"已通过" |
| **后置条件** | 报名状态变为"已取消"；生成站内消息；统计同步变化 |
| **主流程** | 1. Student 在"我的报名"中点击取消<br>2. 系统校验归属（registration.student_id == 当前学生）<br>3. 系统校验状态可取消（待审核/已通过）<br>4. 更新状态为"已取消"<br>5. 写站内消息<br>6. 统计同步：已通过数减少，剩余名额增加 |
| **备选流程** | 2a. 非本人报名 → 提示"无权操作"<br>3a. 状态为"已拒绝"或"已取消" → 提示"该报名状态不可取消" |
| **业务规则** | B.2 规则 4（已取消记录保留历史，允许再次申请）、规则 5 |

---

### UC-05 管理员审批（P2-F05 / P2-F06）

| 项 | 内容 |
|---|---|
| **主参与者** | Admin |
| **前置条件** | 存在状态为"待审核"的报名 |
| **后置条件** | 报名状态变为"已通过"或"已拒绝"；生成站内消息 |
| **主流程（批准）** | 1. Admin 打开待审核列表，点击"批准"<br>2. 系统取出报名记录<br>3. **系统再次检查剩余名额**（业务规则 2）<br>4. 策略返回状态"已通过"<br>5. 更新报名记录（事务提交）<br>6. 写站内消息<br>7. 提示"已批准" |
| **主流程（拒绝）** | 同上，第 3 步跳过（拒绝不占名额），第 4 步策略返回"已拒绝" |
| **备选流程** | 3a. **批准时容量已满 → 批准失败，状态保持"待审核"不变，不发出"已通过"通知**，提示"名额已满，无法批准"<br>3b. 报名状态不是"待审核" → 提示"该报名不可审批" |
| **业务规则** | B.2 规则 2/3 |

---

### UC-06 查看站内消息（P2-F07）

| 项 | 内容 |
|---|---|
| **主参与者** | Student |
| **前置条件** | Student 已登录 |
| **后置条件** | 消息标记为已读（可选操作） |
| **主流程** | 1. Student 打开消息中心<br>2. 系统按创建时间倒序列出该学生的全部消息：内容、关联活动、创建时间、未读标记<br>3. Student 点击消息 → 标记为已读 |
| **备选流程** | 2a. 无消息 → 提示"暂无消息" |
| **说明** | 消息内容涵盖：报名成功、待审核提醒、审批通过、审批拒绝、报名取消 |

---

### UC-07 查看活动统计（P2-F08）

| 项 | 内容 |
|---|---|
| **主参与者** | Student、Admin |
| **前置条件** | 活动存在 |
| **后置条件** | 无 |
| **主流程** | 1. 打开活动详情页或管理端统计页<br>2. 系统实时统计该活动的：**已通过数**、**待审核数**、**剩余名额 = capacity − 已通过数** |
| **说明** | 名额只按"已通过"计算；待审核**不占用**名额（业务规则 3）；取消"已通过"后剩余名额自动回升 |

## 三、业务规则追踪矩阵

| 规则编号（附录 B.2） | 规则要点 | 落在哪个用例 | 代码实现位置 |
|---|---|---|---|
| R1 | 直接报名 → 已通过 + 通知 | UC-03 | `DirectPolicy.submit()` / `RegistrationService.submit()` |
| R2 | 审核型 → 待审核；批准时再查名额 | UC-03、UC-05 | `ReviewPolicy` / `RegistrationService.review()` |
| R3 | 名额按"已通过"计；待审核不占名额；满员不得批 | UC-07、UC-05 | `_check_quota()` / `count_approved()` |
| R4 | 同活动同学生不得两条有效报名；取消/拒绝后可再申请 | UC-03 | `_check_duplicate()` / `has_effective()` |
| R5 | 可取消"待审核/已通过"；活动开始后不收新报名 | UC-04、UC-03 | `cancel()` / `_check_common_rules()` |
| R6 | 通知失败留痕但不使报名消失 | UC-03、UC-05 | `RegistrationService.submit()` 事务边界 / `MessageNotifier.update()` |
| R7 | 持久化；删除有报名的活动要拒绝或软删除 | UC-01 | `ActivityService.delete_activity()`（本设计选**拒绝删除**）|

## 四、字段约束（B.1）

| 对象 | 字段 | 约束 |
|---|---|---|
| Student | student_id | 唯一 |
| | name | 非空 |
| Activity | activity_id | 唯一 |
| | title | 非空 |
| | category | 非空（讲座/比赛/志愿/社团…） |
| | start_at | 合法时间 |
| | location | 非空 |
| | capacity | **正整数** |
| | policy_type | `直接报名` / `审核型` |
| Registration | registration_id | 唯一 |
| | activity_id / student_id | 外键 |
| | status | `待审核` / `已通过` / `已拒绝` / `已取消` |
| Message | message_id | 唯一 |
| | content | 非空 |
| | is_read | 布尔，默认 False |
| | related_registration_id + event_type | **联合唯一**（防重复通知的幂等键）|
